# 城市地下综合管廊运行维护管理平台

面向管廊主体台账、入廊管线登记、廊内环境监测、通风排水消防、结构沉降与渗漏处置、巡检检修与隐患整改、入廊作业审批和运维值班的一体化城市地下综合管廊运行维护管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 消防设施检测链路的统一口径

消防模块不再走通用状态流转，由 `frontend/src/api/fire-inspection.ts` 统一收口，全站只此一份口径：

- 状态机按来源态门控：`待检测 → 检测中 →（判定正常→已结案）/（提出维修→需维修→结案→已结案）`。
  `已结案` 是终态，任何动作都拒绝，结案记录不会再退回检测中；`状态正常` 仅作为改版前（v1）既有记录的原判保留。
- 一次落库：提交检测、判定/维修、结案连同结论、隐患整改清单、值班台账由 `local-store.commit`
  在同一次写入里提交，中途失败整笔不留痕；同一设施同一动作靠动作幂等台账只认第一次，后续整笔按重复退回。
- 唯一事实源：列表、详情抽屉、另存 CSV 都直接读 `local-store` 同一份消防行；详情每次打开/动作后现取，
  关闭即清空草稿与报错，不残留上一轮结论。统计卡片数字全部由行实时计算。
- 校验：缺有效探测器数量（空值/非正整数）的检测单不许提交、不许登记；提出维修/结案必须填写结论。
- 维修结论落到隐患整改清单（`HAZA-FIRE-*`，待整改；结案时回写维修结论并验收）；每产生一份检测结论
  同步一条值班台账（`DUTY-FIRE-*`，含探测器数量等关键数值），消防侧结论数与值班台账来源条数严格相等。
- 新旧口径：新记录一律 v2；既有 v1 记录原判冻结（`状态正常`/`需维修` 不进新流程）。首次加载时执行
  一次性迁移：v1 记录按 `联动测试日` 补 `上次检测日`，`下发日期` 等历史缺值留空并写入 `残缺字段` 标出，
  缺的取值照当时那版留档，不臆造。
- 链路自测：`node frontend/scripts/fire-flow-bundle.cjs`（用 esbuild 打包 `fire-flow-check.ts` 后在 node 中
  以内存版 localStorage 跑完整断言）。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `urban-utility-tunnel:entries` 这一项，或调用 `resetModule(模块)`。
